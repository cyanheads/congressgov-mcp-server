# 0.4.2 — 2026-08-16

## Added

- **Supply-chain guards** — `bunfig.toml` now blocks installing package versions published in the last 3 days (`minimumReleaseAge`, `@cyanheads/mcp-ts-core` excluded for same-day adoption) and scans installs with `@socketsecurity/bun-security-scanner`.
- **Community health files** — `CONTRIBUTING.md`, `CODE_OF_CONDUCT.md`, `SECURITY.md`, `FUNDING.yml`, and `.gitattributes`.

## Changed

- **Upstream HTTP diagnostics** now read from the framework's canonical `error.data.status`/`error.data.body` fields instead of `statusCode`/`responseBody`, and 404 is marked an expected status so a Congress.gov not-found response logs at debug rather than error severity.
- **Docker build** uses BuildKit cache mounts and installs production dependencies with `--omit=peer`, keeping the framework's optional peer tiers (test runner, service SDKs, parsers) out of the runtime image.

## Fixed

- **`congressgov_bill_lookup`/`congressgov_daily_record`** — `billNumber`, `volumeNumber`, and `issueNumber` now accept the digit-string form list rows carry (e.g. `"9479"`), not just a JSON number, so a list row's identifier chains directly into the matching detail call. ([#43](https://github.com/cyanheads/congressgov-mcp-server/issues/43))
- **`congressgov_committee_lookup`** — the filtered `list` result is now paginated by `offset`/`limit` with a real `nextOffset`, instead of returning every match regardless of the caller's page size. ([#44](https://github.com/cyanheads/congressgov-mcp-server/issues/44))
- **`congressgov_committee_lookup`** — `committeeCode` now resolves single-word committee names (e.g. `Judiciary`) the same way multi-word names already did; matching routes on committee-code shape rather than on the presence of whitespace. ([#46](https://github.com/cyanheads/congressgov-mcp-server/issues/46))
- **`congressgov_bill_lookup`/`congressgov_bill_summaries`** — a reversed `fromDateTime`/`toDateTime` pair is now rejected as an input error instead of silently returning an empty result indistinguishable from a genuine no-match. ([#48](https://github.com/cyanheads/congressgov-mcp-server/issues/48))
- **Exhausted-page notices** — a shared `notifyIfNoMatches()` now gates every browse/list tool's no-match enrichment notice on the upstream total, across 22 call sites in 11 tool definitions, so paging past the end of a non-empty result set no longer pairs the accurate "page is empty" text with a contradictory "no matches" notice. ([#49](https://github.com/cyanheads/congressgov-mcp-server/issues/49))
