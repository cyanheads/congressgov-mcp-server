# 0.5.2 — 2026-08-25

## Added

- **Cache hints on the cacheable results** ([mcp-ts-core#359](https://github.com/cyanheads/mcp-ts-core/issues/359)). `createApp({ cacheHints })` marks the catalog operations — `tools/list`, `prompts/list`, `resources/list`, `resources/templates/list`, `server/discover` — cacheable for an hour and `resources/read` for five minutes, both `public`; `congress://bill-types` overrides to a day and `congress://current` to an hour. Honored on protocol revision 2026-07-28 only, so 2025-era responses are unchanged.

## Changed

- **HTTP serves protocol revision `2026-07-28`** alongside the `initialize`-negotiated 2025 revisions, and `/.well-known/mcp.json` reports `mcp_version: 2026-07-28`.
- **Tool arguments are strict** ([mcp-ts-core#232](https://github.com/cyanheads/mcp-ts-core/issues/232)). An argument key no tool declares is rejected by name instead of silently stripped, and every advertised `inputSchema` carries `additionalProperties: false` — a caller who sends `querry` gets an `unrecognized_keys` failure rather than an unfiltered answer.
- **Advertised schemas are JSON Schema 2020-12**, and every tool's `outputSchema` declares the failure envelope ([mcp-ts-core#241](https://github.com/cyanheads/mcp-ts-core/issues/241)): success fields become optional, `error` is declared, and an `anyOf` restores requiredness per branch. A client that validates `structuredContent` without checking `isError` no longer rejects error results with `-32602`.
- **`resources/subscribe` and `logging` are advertised and backed.** `logging/setLevel` resolves, and handler log lines reach the client as `notifications/message` at their RFC 5424 level.
- **The API, document, and Senate LIS services derive their network context from the handler's own context** via `requestContextService.createRequestContext({ parentContext: ctx })`, replacing a local `RequestContextLike` shim — the request ID now carries into upstream fetch logs and retry reports instead of being replaced by a per-service literal.
- **Bun pins move to `1.4.0`** — both `Dockerfile` stages and `packageManager`; `engines.bun` stays `>=1.3.0`. The build stage is pinned to `--platform=$BUILDPLATFORM`, since Bun ≥1.4 aborts under QEMU user-mode emulation and would kill the `linux/amd64` leg of a multi-arch `buildx` run on an arm64 host.
- **`MCP_SESSION_MODE` is documented** in `.env.example` and the README config table: `auto` by default, resolving to `stateful`, while the published Docker image runs `stateless`. No behavior change — the image already set it.
