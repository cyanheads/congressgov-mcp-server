# 0.5.1 — 2026-08-17

## Changed

- **`content` document ceiling raised 5,000,000 → 25,000,000 bytes**, backed by a new incremental extractor (`extract-text-stream.ts`) that extracts text as the body streams and retains only the requested character window instead of buffering the whole document — a read's live set stays flat in size regardless of the document. The largest enacted bills are now reachable in either published format: 116th Congress H.R. 133 is 6,790,482 bytes as Formatted Text and 9,812,888 as XML, both previously refused outright. The extractor is held byte-for-byte identical to the existing whole-string `extract-text.ts`, which remains the normative definition of the extraction, by a differential test ([#56](https://github.com/cyanheads/congressgov-mcp-server/issues/56)).
- **`document_too_large` recovery hint** no longer points callers at the other format, which fails the same way — it names the `sourceUrl` instead.

## Fixed

- **A document body that fails mid-stream now maps to `document_fetch_failed`** instead of surfacing an unmapped, retried `Error`.
